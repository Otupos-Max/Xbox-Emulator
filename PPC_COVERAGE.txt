Inventário de instruções PowerPC que o interpretador precisa emular para
executar: (a) testes unitários, (b) hello world homebrew, (c) jogos
comerciais. Prioridades:

  [T] Testes — necessária para validar o interpretador em si.
  [H] Hello world — necessária para o primeiro XEX homebrew.
  [G] Jogo comercial — necessária para jogos reais.

Status:
  [ ] Não implementada
  [~] Stub (decodifica, não executa corretamente)
  [P] Parcial (executa casos simples, não todos os edge cases)
  [X] Completa (passa testes de referência)
  [V] Validada (passa testes cruzados com hardware real ou referência)

================================================================================
13. RESUMO DE PRIORIDADES
================================================================================

FASE 1 (T) — Testes unitários, antes de qualquer coisa:
  aritmética básica, lógica, rlwinm/rlwimi, loads/stores básicos,
  branches básicos, mfspr/mtspr, fadd/fmul básicos.

FASE 2 (H) — Hello world homebrew:
  tudo de Fase 1 + sc, mtcr/mfcr, mftb, mfspr de LR/CTR,
  carregamento de vetor (lvx/stvx), vaddubm, vspltisb.

FASE 3 (G) — Jogos comerciais:
  toda a ISA acima, com prioridade em VMX (seção 11) e atômicos
  (seção 12).


================================================================================
14. TESTES DE REFERÊNCIA
================================================================================

Toda instrução deve ter teste unitário na pasta Tests/PPC/ com:
  - Caso base (valores típicos).
  - Casos de borda (overflow, underflow, máximo/mínimo, zero).
  - Casos de CR update (instruções com sufixo ".").
  - Casos de XER update (overflow, carry).

Testes cruzados com hardware real são ideais mas não obrigatórios para
todas as instruções — usar QEMU-PPC ou PowerPC emulador de referência
como oráculo secundário quando possível.

Cobertura-alvo para M1: >90% das instruções com [T] implementadas e
testadas.
